1. Introduction

This Privacy Policy describes how SIPLX ("we", "our", "the app") handles user data. SIPLX is an Android text expansion application that allows you to create shortcuts (trigger phrases) that expand into full text snippets.

Core Principle: SIPLX is designed as a local-first, privacy-respecting application. All text expansion processing occurs entirely on your device. We do not collect, transmit, or share your personal data.

2. Information We Collect

SIPLX collects the minimum data necessary to provide its text expansion functionality. All data listed below is stored locally on your device only.

2.1 Snippet Content and Triggers

  • What: The snippets you create (the expanded text) and their associated trigger phrases (shortcuts)
  • Where stored: Local Room database (siplx.db) on your device
  • Purpose: To perform text expansion when you type a trigger phrase in any text field
  • Transmission: None — all snippet data remains on your device

2.2 App Preferences and Settings

  • What: Your app configuration, including theme selection, language preference, trigger mode, and workspace state
  • Where stored: Local DataStore preferences file on your device
  • Purpose: To maintain your personalized app experience across sessions
  • Transmission: None

2.3 Expansion Statistics

  • What: Count of text expansions performed, timestamps, and which snippets were expanded
  • Where stored: Local Room database (siplx.db) on your device
  • Purpose: To display usage statistics in the Statistics screen
  • Transmission: None

2.4 Account Preferences

  • What: Your selected account type (Guest, Google, Email, or Team), subscription tier preference, and cloud sync preference
  • Where stored: Local DataStore preferences file on your device
  • Purpose: UI state management for future account and subscription features
  • Note: Account features are not yet implemented. Cloud sync is not yet available. These values are purely local preferences at this time.
  • Transmission: None

2.5 Team Data

  • What: Team names, workspace configurations, shared snippets, member roles, and activity records
  • Where stored: Local Room database (siplx.db) on your device
  • Purpose: To support team collaboration features that operate entirely on-device
  • Note: Team features operate over a local-only database. There is no server infrastructure for team data.
  • Transmission: None

2.6 Premium Tier Preference

  • What: Your selected premium tier (Free, Pro, or Team)
  • Where stored: Local DataStore preferences file on your device
  • Purpose: To unlock different feature sets within the app
  • Note: Premium tier is stored as a local preference only. There is no server-side verification of subscription status.
  • Transmission: None

4. Accessibility Service Usage

SIPLX uses the Android Accessibility Service exclusively for its core feature: automatic text expansion.

4.1 Why the Accessibility Service Is Required

Android does not provide a standard API for intercepting and replacing text as the user types across all applications. The Accessibility Service is the only mechanism that allows SIPLX to:

  1. Monitor text input fields across any app
  2. Detect when a trigger phrase has been typed
  3. Replace the trigger phrase with the corresponding snippet

4.2 What We Monitor

Event TypePurpose
typeViewTextChangedDetect trigger phrases being typed in text fields
typeViewFocusedIdentify which text field the user is interacting with
typeWindowStateChangedDetect app switches and window changes

4.3 What We Do NOT Do

  • ✘ We do not record keystrokes permanently
  • ✘ We do not transmit any text to external servers
  • ✘ We do not perform gestures on your behalf (canPerformGestures="false")
  • ✘ We do not access content outside of text input fields unnecessarily
  • ✘ We do not collect data for advertising, analytics, or profiling

4.4 Data Retention

When a trigger phrase is matched, the typed characters that formed the trigger are replaced with the expanded snippet. The original trigger text is not stored beyond the expansion moment.

The Accessibility Service operates in a stateless manner with respect to monitored text — it only processes the current text buffer to detect trigger matches. Historical typed content is not maintained.

4.5 Disclosure

The Accessibility Service is prominently disclosed:

"SIPLX monitors text you type to expand short trigger phrases into full text snippets. All processing happens locally on your device. No text is sent to external servers."

This disclosure appears in the system Accessibility settings and the app's About screen.

5. Clipboard Management

5.1 Text Expansion Clipboard Use

For text expansion in certain applications where direct text injection is not possible, SIPLX uses a fallback strategy that temporarily accesses the system clipboard:

  1. Save: The current clipboard content is saved to memory
  2. Set: The snippet text is placed on the clipboard
  3. Paste: A programmatic paste action (ACTION_PASTE) is performed
  4. Restore: The original clipboard content is restored

This clipboard operation is temporary and ephemeral. The snippet text remains on the clipboard only for the duration of the paste operation (milliseconds).

5.2 Clipboard History (Future Feature)

SIPLX contains a clipboard_history table in its local database. Current status: The schema and DAO are defined but the clipboard history feature is not yet active in the user interface. This is preparatory code for a future feature.

5.3 What We Do NOT Do with the Clipboard

  • ✘ We do not transmit clipboard contents to any server
  • ✘ We do not persistently store clipboard contents beyond the expansion operation
  • ✘ We do not monitor the clipboard passively in the background
  • ✘ We do not share clipboard data with third parties

7. Import and Export

SIPLX supports manual import and export of snippet data for user-controlled backup and migration.

7.1 Export

  • Format: JSON (via Gson library)
  • Method: Android Storage Access Framework (SAF) — user selects the save location
  • Content: All user snippets, triggers, folders, and metadata
  • Scope: Local file export only — no network transmission

7.2 Import

  • Format: JSON
  • Method: Android SAF file picker — user selects the file to import
  • Conflict resolution: Options include Keep Existing, Overwrite, and Keep Both
  • Scope: Local file import only — no network retrieval

7.3 Data Control

Users have full control over their data through:

  • Export: Full backup of all snippets to a user-chosen location
  • Import: Restoration of snippets from a user-chosen backup file
  • Delete: Individual snippet deletion or bulk deletion within the app

10. Data Security

10.1 On-Device Processing

All data processing occurs on your device. No data transmission means no risk of interception during transit.

10.2 Local Storage Security

  • Data is stored in the app's private internal storage directory
  • Android's sandboxing prevents other applications from accessing SIPLX's data
  • Room database is not encrypted at rest in the current version (standard for local-only apps)
  • No data is stored in shared storage locations

10.3 Code Protection

  • Release builds are minified and obfuscated via R8
  • Debug logging (Log.v, Log.d, Log.i) is stripped from release builds
  • ProGuard rules are configured to maintain correct functionality after obfuscation

11. Data Retention and Deletion

11.1 Retention

Data is retained on your device for as long as you use the application. There is no server-side data retention because no data is transmitted.

Clipboard content accessed during text expansion is:

  • Used exclusively for the paste operation
  • Restored to the original content immediately after expansion
  • Not persisted beyond the expansion operation

12. Children's Privacy

SIPLX is not directed at children under the age of 13. We do not knowingly collect any personal information from children under 13. If we become aware that a child under 13 has provided us with personal information, we will delete that information promptly.

Since SIPLX does not collect, transmit, or store any personal information from any user — including children — there is no risk of children's data being collected or shared.
